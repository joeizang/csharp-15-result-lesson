2. Give your value object a Result factory

A union can hold a value of any one of its declared case types. A Result uses that feature to represent success or failure. Here, Ok<T> and Err<E> keep the roles distinct even if both payloads share a type. Each wrapper converts implicitly to the enclosing union. Union syntax and conversions.

Domain.cs

public sealed record Ok<T>(T Value);
public sealed record Err<E>(E Error);
public union Result<T, E>(Ok<T>, Err<E>);

public sealed record QuantityOutOfRange(int Attempted);

public sealed record Quantity
{
    public int Value { get; }
    private Quantity(int value) => Value = value;

    public static Result<Quantity, QuantityOutOfRange> Create(int value)
    {
        if (value is < 1 or > 100)
            return new Err<QuantityOutOfRange>(new QuantityOutOfRange(value));

        return new Ok<Quantity>(new Quantity(value));
    }
}

The private constructor and read-only property keep construction behind the range check. The input is already an int because the HTTP layer handles JSON binding. For text input you parse yourself, use int.TryParse and return a separate error for malformed input. Microsoft’s guidance on Try methods.

3. Return a storage outcome

Persistence.cs

using System.Collections.Concurrent;

public sealed record Item(Guid Id, Quantity Quantity);
public sealed record DuplicateItem(Guid Id);

public sealed class ItemStore
{
    private readonly ConcurrentDictionary<Guid, Item> items = new();

    public Result<Item, DuplicateItem> Add(Item item)
    {
        if (items.TryAdd(item.Id, item))
            return new Ok<Item>(item);

        return new Err<DuplicateItem>(new DuplicateItem(item.Id));
    }

    public bool TryGet(Guid id, out Item? item) =>
        items.TryGetValue(id, out item);
}

This sample uses in-memory storage. TryAdd checks for a duplicate and inserts in one operation, so two requests cannot both create the same ID. Data lasts for the process lifetime.

In a database adapter, let a unique constraint enforce the same rule under concurrency. If your provider reports violations as exceptions, translate the documented violation for that constraint into a conflict. A generic database exception can have several causes. Preserve meaningful distinctions such as cancellation, conflict, and an unavailable store. Exception handling and cancellation.

4. Give distinct failures distinct types

Milan Jovanović’s article shows a useful progression. A generic Result can replace a hand-written success flag. If every failure still uses the same error record and differs only by its string code, adding a new code leaves the union’s set of types unchanged. A separate type for each failure lets a switch report a newly missing case. Use typed errors where the caller needs to make different decisions. Can C# 15 Union Types Replace the Result Pattern?

Application.cs

public sealed record UnexpectedState;
public union CreateItemError(QuantityOutOfRange, DuplicateItem, UnexpectedState);

public sealed class CreateItem(ItemStore store)
{
    public Result<Item, CreateItemError> Handle(Guid id, int rawQuantity) =>
        Quantity.Create(rawQuantity) switch
        {
            Ok<Quantity> ok => Save(new Item(id, ok.Value)),
            Err<QuantityOutOfRange> err => Fail(err.Error),
            null => Fail(new UnexpectedState())
        };

    private Result<Item, CreateItemError> Save(Item item) =>
        store.Add(item) switch
        {
            Ok<Item> ok => ok,
            Err<DuplicateItem> err => Fail(err.Error),
            null => Fail(new UnexpectedState())
        };

    private static Result<Item, CreateItemError> Fail(CreateItemError error) =>
        new Err<CreateItemError>(error);
}

Only Ok<Quantity> reaches Save. The use case combines the domain and storage errors into its own error vocabulary. There are two union levels. The outer switch distinguishes Ok and Err. The inner HTTP switch distinguishes the types held inside Err.

Handle empty contents explicitly. A generated union is a struct whose default value has null contents. A switch can throw if that value reaches it without a matching arm, even when the compiler accepted the other arms. Use a specific null arm so the compiler can still flag new case types. Union exhaustiveness and null.

5. Map outcomes to HTTP

Program.cs

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<ItemStore>();
builder.Services.AddSingleton<CreateItem>();

var app = builder.Build();

app.MapGet("/items/{id:guid}", IResult (Guid id, ItemStore store) =>
    store.TryGet(id, out Item? item) && item is not null
        ? Results.Ok(new ItemResponse(item.Id, item.Quantity.Value))
        : Results.NotFound());

app.MapPost("/items", IResult (CreateItemRequest request, CreateItem useCase) =>
    useCase.Handle(request.Id, request.Quantity) switch
    {
        Ok<Item> ok => Results.Created(
            $"/items/{ok.Value.Id}",
            new ItemResponse(ok.Value.Id, ok.Value.Quantity.Value)),
        Err<CreateItemError> err => ToHttpError(err.Error),
        null => Results.Problem()
    });

app.Run();

static IResult ToHttpError(CreateItemError error) => error switch
{
    QuantityOutOfRange invalid => Results.BadRequest(new
    {
        code = "quantity.out_of_range",
        attempted = invalid.Attempted
    }),
    DuplicateItem duplicate => Results.Conflict(new
    {
        code = "item.duplicate",
        id = duplicate.Id
    }),
    UnexpectedState => Results.Problem(),
    null => Results.Problem()
};

public sealed record CreateItemRequest(Guid Id, int Quantity);
public sealed record ItemResponse(Guid Id, int Quantity);

What this guarantees about exceptions

Every modeled outcome in the sample uses an ordinary return and there are no explicit throw statements. A Result return type places no restriction on what a dependency, framework, runtime, or awaited operation can throw. Catching and translating a provider exception changes what the caller receives after the exception has occurred.

Use documented nonthrowing operations for expected failures where available. Keep documented, recoverable provider exceptions at the adapter boundary and decide whether cancellation should be a canceled task or an explicit outcome. Handle and log unexpected faults at the host boundary where recovery is possible. A literal guarantee that no exception is ever thrown anywhere remains outside this design. Microsoft’s exception guidance.

Practice

Predict each answer before revealing it.

What happens to storage when Create receives 0?

The domain returns Err<QuantityOutOfRange>. The use case forwards the error and skips storage.

What happens if you add a case to CreateItemError?

Add a public sealed record ItemLimitReached; and list it in the union. Keep ToHttpError unchanged and build. CS8509 points to the missing arm. Add an arm that matches your API contract, then rebuild.

Why keep the null arm if all the case types are nonnullable?

A generated union can be default initialized, which leaves it with null contents. An explicit arm handles that state while preserving missing-case diagnostics.
